4小机在背后做了什么

  1. 下载一个 Python 小脚本（ns_play_history.py，只用标准库）。
  2. auth-url：生成任天堂官方登录链接，交给你。
  3. auth-finish：读入你复制的授权链接，在你电脑上保存登录凭证（约两年有效，仅你可读）。
  4. fetch：读取全部游玩记录，存成 play_histories.json。

想自己动手也行：python3 ns_play_history.py login 交互式登录，然后 fetch。

5它是怎么工作的

脚本做的事和 Nintendo Store app 一样：先用任天堂账号登录，再读取「我的游玩记录」。全程是普通的 HTTPS 请求。

① 登录（Nintendo Account 的 OAuth + PKCE）

使用 Nintendo Store app 的登录入口，所以确认页上写的是「关联到 Nintendo Store」。

参数值
client_id5c38e31cd085304b
redirect_urinpf5c38e31cd085304b://auth
scopeopenid user user.mii user.email user.links[].id
response_typesession_token_code（配合 S256 的 code challenge）
POST https://accounts.nintendo.com/connect/1.0.0/api/session_token
client_id=5c38e31cd085304b
session_token_code=<授权链接里的>
session_token_code_verifier=<生成 challenge 用的随机串>
# → { "session_token": "…" }   约两年有效
② 换访问凭证 
POST https://accounts.nintendo.com/connect/1.0.0/api/token
{ "client_id": "5c38e31cd085304b",
  "session_token": "…",
  "grant_type": "urn:ietf:params:oauth:grant-type:jwt-bearer-session-token" }
# → { "access_token": "…", "expires_in": 900 }
③ 读取游玩记录 
curl https://app-api.znej.nintendo.com/api/v2.0/users/me/play_histories \
  -H "Authorization: Bearer $ACCESS_TOKEN" \
  -H "gentry-locale: en-US"
gentry-locale 是必填的：不带会返回 400（报错不会告诉你缺的是哪个头）。它也决定游戏名用什么语言，比如 ja-JP、zh-TW。

7常见问题

为什么确认页写着「关联到 Nintendo Store」？

因为用的是 Nintendo Store app 的登录入口——这份游玩记录本来就是给这个 app 显示的。登录、确认都在任天堂官方页面完成，脚本和小机都拿不到你的密码。

安全吗？会不会改动我的账号？

只读取游玩记录，不做任何修改。登录凭证只保存在你自己电脑的 ~/.ns-play-history/ 里（仅你可读）；不想用了，删掉这个文件夹即可。

按天的记录为什么只有一周？

接口只提供最近一周的按天明细，累计时长则一直保留。想让小机一直知道你每天玩了什么，就让 ta 每天或每次聊天前 fetch 一次，把每次的文件存起来。

不想被问的时候呢？

直接跟小机说就好。llms.txt 里也写了：像伴侣那样自然地提起，你不想聊的时候就别追问。

以前的导出工具为什么都不能用了？

2025 年 11 月 5 日，日区的 My Nintendo app 更名为 Nintendo Store，读取游玩记录的地址也随之更换，旧地址停止服务。本页用的是更名后的新地址。

哪些地区的账号能用？3DS / Wii U 呢？

实测澳洲区账号可用，其他地区理论上相同，欢迎反馈。3DS / Wii U 的记录（如果账号关联过）只到 2020 年 2 月。

ℹ️ 这个接口没有公开文档，任天堂可能随时调整。请只用于查看你自己的账号。
